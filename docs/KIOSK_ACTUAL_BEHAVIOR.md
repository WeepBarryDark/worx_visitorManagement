## 🔍 技术原理

### 为什么应用无法完全阻止？

```dart
// 当前实现
PopScope(
  canPop: false,  // ← 只能阻止Flutter路由导航
  child: GestureDetector(
    onHorizontalDragStart: (details) {
      // ← 只能检测触摸事件
      // ❌ 无法阻止系统级手势
      _showExitWarning();
    },
  ),
)
```

**系统级操作优先级：**
```
优先级1: 系统手势（主页、控制中心）
  ↓ (应用无法拦截)
优先级2: 应用层拦截 ← 我们的KioskGuard在这里
  ↓
优先级3: 应用内导航
```

### 操作系统的安全限制

**Android:**
```java
// 系统级代码（应用无权访问）
if (user presses home button) {
    // 强制返回主屏幕
    // 应用无法拦截此操作
    goToHomeScreen();
}
```

**iOS:**
```swift
// 系统级代码（应用无权访问）
if (user swipes from bottom) {
    // 强制返回主屏幕
    // 应用无法拦截此操作
    dismissToHomeScreen();
}
```

这是**故意设计**的安全机制，防止恶意应用锁住设备。

## ✅ 当前代码实际提供的保护

### 1. 返回键拦截（Android）
```dart
PopScope(canPop: false)
```
- ✅ 拦截Flutter导航返回
- 🟡 第一次按返回键显示警告
- ⚠️ 用户坚持按会退出（除非启用屏幕固定）

### 2. 手势检测（iOS）
```dart
GestureDetector(
  onHorizontalDragStart: (details) {
    if (details.globalPosition.dx < 30) {
      _showExitWarning();  // 显示警告
    }
  }
)
```
- ✅ 检测边缘滑动
- 🟡 显示警告提示
- ⚠️ 无法真正阻止系统手势

### 3. 沉浸式模式
```dart
SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky)
```
- ✅ 隐藏系统导航栏
- ✅ 全屏显示
- ⚠️ 用户滑动边缘仍会暂时显示导航栏

### 4. 防休眠
```dart
WakelockPlus.enable()
```
- ✅ 屏幕保持唤醒
- ✅ 不会自动锁屏

## ⚠️ 常见误区

### 误区1: "应用可以完全锁住设备"
```
❌ 错误理解:
"修改了KioskGuard后，用户无法退出应用"

✅ 正确理解:
"应用提供警告和提示，但系统级退出仍需设备配置"
```

### 误区2: "PopScope可以阻止所有退出"
```
❌ 错误理解:
"PopScope(canPop: false) 阻止所有退出方式"

✅ 正确理解:
"PopScope只阻止Flutter路由导航，不阻止系统级操作"
```

### 误区3: "手势检测 = 手势阻止"
```
❌ 错误理解:
"GestureDetector检测到手势就能阻止"

✅ 正确理解:
"GestureDetector只能检测和显示警告，无法阻止系统手势"
```
